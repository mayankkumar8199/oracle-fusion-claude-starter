## 3. Order-to-Cash (O2C) end to end

This section follows one sales order from customer master data to cleared cash and a closed period. Each step shows the purpose, job roles, UI entry point, tables, status columns, REST resources, bulk and scheduled-process interfaces, and controls. Conventions:

- Tables are written TABLE (PK). REST resource names are roots under `/fscmRestApi/resources/11.13.18.05/` unless marked `/crmRestApi`.
- "(verify in your pod)" marks values that Oracle does not document precisely or that depend on your setup.
- Related sections: interface mechanics in 6 and 7, accounting backbone in 4, SQL patterns in 9, Oracle AI agents in 10, Claude Code in 11, security in 12.

| Key controls and exceptions | The customer must exist before import. Import Sales Orders is case-sensitive; the template uses Y/N and REST uses true/false. Credit check (parameter Activate Credit Check on Order Submit) runs at submit and immediately before approval, and reruns when an attribute that affects payment, such as Bill-To Customer, changes or a revision is submitted. Credit hold on the customer credit profile puts existing orders on hold, and AutoInvoice can't import that customer's Order Management invoices (manual transactions still work). Processing constraints block changes by status and role. Agent actions are audited in DOO_AGENT_ACTION_HISTORY (AGENT_EXECUTION_MODE such as HUMAN_ASSIST or AUTO). |

### 3.4 Orchestration and fulfillment

The predefined ShipOrderGenericProcess runs these steps in sequence (task service in brackets): 100 Schedule (Create Scheduling), 200 Create Reservation (Create Inventory Reservation), 300 Create Shipment Request (Create Shipping), 400 Wait for Shipment Advice (Wait for Shipment), 500 Create Invoice (Create Billing Lines), 600 Wait for Invoice (Wait for Billing). A hold stops the process before the next task; holds applied while Order Management compensates a change are released automatically when compensation finishes.

| Item | Detail |

-- O2C spine queries. Read-only. Bind :order_number, :trx_number or :statement_header_id.
-- Revised orders keep earlier header versions (status Reference); filter to the version you need.

-- 1. Order -> fulfillment line -> shipment -> invoice line -> installment -> receipt application
--    (wide join; for a one-row-per-document timeline with a BU filter see section 9, Q8)
SELECT dha.order_number,
       dha.status_code               AS order_status,
       dla.line_number,
       dfla.fulfill_line_id,
       dfla.status_code              AS fline_status,
       dfla.invoice_interface_status,
       wdd.delivery_detail_id,
       wdd.released_status,
       wnd.delivery_name,
       wnd.status_code               AS shipment_status,
       rcta.trx_number,
       rctla.interface_line_context,
       rctla.line_number             AS trx_line_number,
       rctla.extended_amount,
       aps.payment_schedule_id,
       aps.status                    AS installment_status,
       aps.amount_due_remaining,
       acra.receipt_number,
       acrh.status                   AS receipt_state,
       araa.amount_applied,
       araa.status                   AS application_status
FROM   doo_headers_all dha
JOIN   doo_lines_all dla              ON dla.header_id = dha.header_id
JOIN   doo_fulfill_lines_all dfla     ON dfla.line_id = dla.line_id
LEFT   JOIN wsh_delivery_details wdd  ON wdd.source_shipment_id = dfla.fulfill_line_id
LEFT   JOIN wsh_delivery_assignments wda ON wda.delivery_detail_id = wdd.delivery_detail_id
LEFT   JOIN wsh_new_deliveries wnd    ON wnd.delivery_id = wda.delivery_id
LEFT   JOIN ra_customer_trx_lines_all rctla
       ON  rctla.interface_line_attribute5 = TO_CHAR(dfla.fulfill_line_id)
       AND rctla.sales_order = dha.order_number
       AND rctla.line_type = 'LINE'
LEFT   JOIN ra_customer_trx_all rcta  ON rcta.customer_trx_id = rctla.customer_trx_id
LEFT   JOIN ar_payment_schedules_all aps ON aps.customer_trx_id = rcta.customer_trx_id
LEFT   JOIN ar_receivable_applications_all araa
       ON  araa.applied_payment_schedule_id = aps.payment_schedule_id
       AND araa.application_type = 'CASH'
       AND araa.display = 'Y'
LEFT   JOIN ar_cash_receipts_all acra ON acra.cash_receipt_id = araa.cash_receipt_id
LEFT   JOIN ar_cash_receipt_history_all acrh
       ON  acrh.cash_receipt_id = acra.cash_receipt_id
       AND acrh.current_record_flag = 'Y'
WHERE  dha.order_number = :order_number
ORDER  BY dla.line_number, dfla.fulfill_line_id;

-- 2. Invoice -> bill-to site use -> account site -> account -> party; party site -> location; current account profile
SELECT rcta2.trx_number,
       hp.party_number,
       hp.party_name,
       hca.account_number,
       hcsu.site_use_code,
       hcsu.location                 AS site_use_location,
       hl.address1,
       hl.city,
       hl.country,
       hcp.credit_checking,
       hcp.credit_hold,
       hcpa.currency_code,
       hcpa.overall_credit_limit
FROM   ra_customer_trx_all rcta2
JOIN   hz_cust_site_uses_all hcsu     ON hcsu.site_use_id = rcta2.bill_to_site_use_id
JOIN   hz_cust_acct_sites_all hcas    ON hcas.cust_acct_site_id = hcsu.cust_acct_site_id
JOIN   hz_cust_accounts hca           ON hca.cust_account_id = hcas.cust_account_id
JOIN   hz_parties hp                  ON hp.party_id = hca.party_id
JOIN   hz_party_sites hps             ON hps.party_site_id = hcas.party_site_id
JOIN   hz_locations hl                ON hl.location_id = hps.location_id
LEFT   JOIN hz_customer_profiles_f hcp
       ON  hcp.cust_account_id = hca.cust_account_id
       AND hcp.site_use_id IS NULL
       AND SYSDATE BETWEEN hcp.effective_start_date AND hcp.effective_end_date

WHERE  rcta5.trx_number = :trx_number;

SELECT dh9.order_number, dfl9.fulfill_line_id, dfl9.credit_chk_auth_num,

SELECT vsd.document_number, vsd.document_type, vcch.customer_contract_number,

-- 8. Billing lines still in the AutoInvoice interface (and the context Order Management uses in your pod)
SELECT rila.interface_line_context, rila.interface_line_attribute1, rila.interface_line_attribute5,
       rila.batch_source_name, rila.interface_status, rila.request_id,

SELECT csl.statement_line_id, csl.amount, csl.recon_status,

WHERE  csl.statement_header_id = :statement_header_id;
